# Support

Use [GitHub Issues](https://github.com/EitanWong/com.eitan.mnn/issues) for bugs and
feature requests. Search existing issues and check the
[platform and test limits](../Testing.md) before opening a report.

A useful inference report includes Unity and package commit/version, operating
system, architecture, scripting backend, selected MNN backend and precision,
model repository/revision, expected output, actual output and a minimal reproduction.
For a regression, include the last known working commit when available.

Attach the relevant error excerpt and a small reproduction project or script.
Remove tokens, credentials and private paths or content. Do not attach model
weights or full memory dumps. Explain how to obtain a public model or a small,
redistributable fixture instead.

Feature requests should describe the intended workflow and the limitation in the
current API. Platform requests need a concrete compiler/ABI and validation plan.
Support is community-based; there is no guaranteed response time.

For vulnerabilities, follow the [security policy](Security.md).
